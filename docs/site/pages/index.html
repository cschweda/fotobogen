How it runs

Fotobogen is a server application, like WordPress. It runs on one machine and you use it from any web browser. That machine can be a small rented Linux server, which is how a public site is run, or your own Mac or PC, which is the quickest way to try it.

  • The machine needs either Node.js 24 or Docker. Nothing is compiled during installation.
  • Everything a site owns is kept in one folder, called data: the database, your photographs as you uploaded them, and the resized copies.
  • There is one admin account, created in a short setup wizard the first time you open the site.
  • It makes no outside requests unless you ask: downloading sample photos, checking for a new version, and sending webhooks are each switched on by you.

Where it stands

The current version is 1.3.1, of 16 November 2026. It follows 1.3.0, 1.2.0, 1.1.0, which added updating from the admin, and 1.0.0, the first release. What is in each.

Every change is installed, built, and tested on Linux (Ubuntu) and on Windows, and it is developed on macOS. A ready-made Docker image is published for each release.

One thing to know: it has not yet been tried on a Laravel Forge server or on a real 1 GB server. A 1 GB memory limit was tested in Docker.

Your photographs are your responsibility. Fotobogen is free software provided as it is, with no warranty. If the server is lost and you have no backup, the photographs on it are gone. How to back up.

For developers

Fotobogen is built to be extended without touching its code. Two guides take you from an empty folder to something working:

  • Writing a skin: change how a site looks, with a stylesheet and a settings file. If you can write CSS, you can write one.
  • Writing a module: change how photographs look, with a small file of plain JavaScript. No build step, no package to publish, no admin code.
